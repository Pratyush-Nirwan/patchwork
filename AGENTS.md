# Patchwork Agent & Contributor Standing Rules

1. **No Docker**: Everything runs natively on Windows 10/11 and Linux (Ubuntu 22.04/24.04, Debian 12; x64 & arm64).
2. **All scripts are Node.js**: Write all tooling in `.mjs` or `.ts`. Do not add `.sh`, `.bat`, or `.ps1` scripts. Keep `package.json` scripts shell-agnostic (`cross-env`, `scripts/run-chain.mjs`).
3. **Single platform helper**: Only `scripts/lib/platform.mjs` and `src/lib/platform.ts` may read `process.platform` or `process.arch`.
4. **Path & process safety**: Always use Node `path` APIs, `os.tmpdir()`, `shell: false` on `spawn`/`execFileSync`, and `sanitizeFilename()` for user-facing or exported filenames.
5. **LF line endings**: Keep LF (`\n`) across code, generated configs, and SQL per `.gitattributes` and `.editorconfig`.
6. **Testing & CI**: Run tests against `patchwork_test` and a temporary MinIO data directory. Any feature touching filesystems, processes, or services must include cross-platform tests and pass CI on both Windows and Linux.
7. **Documentation & Website**: Documentation and the public website live in the separate [`patchwork-website`](https://github.com/Pratyush-Nirwan/patchwork-website) repository (`https://getpatchwork.in/documentation/`). Regenerate `README.md` with `npm run readme:generate` and pass `npm run readme:check`. Add one changelog entry under `## [Unreleased]` in `CHANGELOG.md` (`**<Scope>:**` tag, plain language, under 140 characters). Never leave docs describing behavior that no longer exists. Never document behavior that is not implemented.
8. **UI Motion & Skeletons**: Animate only `transform` and `opacity` using the shared motion tokens and primitives (`src/lib/motion.ts`, `src/components/ui/motion.tsx`, `src/components/ui/skeleton.tsx`). Every data-dependent region ships a geometry-matched skeleton inside a `Surface` (`data-sk-surface`), uses only surface-derived skeleton tokens (`--sk-surface`, `--sk-base`, `--sk-shine`), has an error boundary and empty state, respects `prefers-reduced-motion`, `prefers-contrast: more`, `forced-colors`, and `patchwork_reduce_motion`, wraps storage access in `try/catch`, uses anti-flash (`150ms` delay / `300ms` hold) and stale-while-revalidate patterns, and passes `npm run loading:check` (`scripts/check-loading-states.mjs`).
9. **Versioning**: Never hardcode a version anywhere; always read it from the version helper (`src/lib/version.ts` for the app, `scripts/lib/version.mjs` for scripts). Always display the version as `v` plus SemVer (for example `v0.7.0-beta`, never without `v` or with a space). Any release bump must use `npm run release:prepare -- <version>` and pass `npm run version:check`.
10. **Easy Install & MinIO**: MinIO is the only attachment storage and must never be replaced by local file storage or another backend (no `STORAGE_DRIVER` or storage-driver abstraction). The default install path (`npm run setup` Easy mode) stays at Node.js plus git only. Any new runtime dependency, service, or system requirement must be provisioned by the installer in Easy mode, documented, checksum-verified if downloaded, and covered by the clean-environment end-to-end install test (`tests/easy-install.test.ts`).
11. **Roadmap & Planned Features**: Planned for `v1.0.0` (see `https://getpatchwork.in/documentation/project/roadmap/`). Do not implement these unless explicitly asked. Document them only as Planned. When one ships, update `CHANGELOG.md` and `patchwork-website`. Out of scope (not on the roadmap): Docker, desktop apps, and mobile apps.
12. **Dev Server Workflow**: During interactive development, the user runs `npm run dev`. Verify edits with `npm run typecheck` (and targeted tests) only — do **not** run `npm run build` or `npm run build:app` unless explicitly requested, as `next build` overwrites `.next/` and breaks hot reload in the running dev server.
