This guide is for system administrators installing or maintaining Patchwork ({versionLabel}) in production or local environments without Docker.

<Aside type="caution" title="Beta software">
  Patchwork {versionLabel} is pre-1.0 beta software. Features and data formats may change between releases. Back up PostgreSQL, `.env`, and MinIO data before upgrading, and report issues on the project issue tracker.
</Aside>

## Prerequisites

- **Node.js 20+**
- **PostgreSQL 16+**
- **Official MinIO binary** (x64 or arm64)

## Step 1: Prepare PostgreSQL & MinIO Binary

<Tabs>
  <TabItem label="Windows (PowerShell)">
    ```powershell
    winget install OpenJS.NodeJS.LTS
    winget install PostgreSQL.PostgreSQL
    New-Item -ItemType Directory -Force -Path .\bin
    Invoke-WebRequest -Uri "https://dl.min.io/server/minio/release/windows-amd64/minio.exe" -OutFile .\bin\minio.exe
    ```
    Add `C:\Program Files\PostgreSQL\<version>\bin` to `PATH` if `psql` or `pg_dump` are not recognized.
  </TabItem>
  <TabItem label="Linux (bash)">
    ```bash
    sudo apt update && sudo apt install -y curl postgresql postgresql-contrib
    mkdir -p ./bin
    # Use linux-arm64/minio on ARM64 hosts
    curl -fsSL "https://dl.min.io/server/minio/release/linux-amd64/minio" -o ./bin/minio
    chmod +x ./bin/minio
    ```
  </TabItem>
</Tabs>

## Step 2: Run the CLI Installer

```bash
npm ci
npm run setup
```

`scripts/setup.mjs` handles fresh installs, repair, reset, and status inspection:

- `--check`: Detect and print current installation status without making changes.
- `--non-interactive`: Read configuration from environment variables (`SETUP_ACTION=repair|reset|status`).
- `--dev`: Start with `npm run dev` instead of production `npm run build && npm run start`.
- `--no-start` / `--no-open`: Skip starting the server or opening the browser.

See [Installer CLI Reference](/reference/installer-cli/) for every flag.

## The Admin Setup Token

During a fresh install, `scripts/setup.mjs` generates a high-entropy Admin Setup Token, encrypts it with `AES-256-GCM` using `TOKEN_ENCRYPTION_KEY`, stores the ciphertext in PostgreSQL, and displays the token once.

<Aside type="caution">
The Admin Setup Token cannot be re-displayed or recovered. Never regenerate `TOKEN_ENCRYPTION_KEY` before `/setup` is completed. If you lose the token, run `npm run setup` and choose **Reset** (`--action=reset`).
</Aside>

## File Permissions & Services

- **Windows**: The installer locks `.env` with `icacls` to your Windows account. Run the server in a terminal or via Windows Task Scheduler / NSSM running `npm run start`.
- **Linux**: The installer sets `chmod 600 .env`, supports PostgreSQL peer auth via `sudo -u postgres`, and installs hardened systemd units (`deploy/patchwork.service` and `deploy/minio.service`) with `ProtectSystem=strict` and `NoNewPrivileges=true`.

## Upgrading

```bash
npm ci
npm run db:migrate
npm run build
```

Restart the service (`sudo systemctl restart patchwork.service` on Linux, or `npm run stop` then `npm run start`). Patchwork also runs idempotent SQL migrations on startup via `src/instrumentation.ts`.

## Backups & Restore

<Tabs>
  <TabItem label="Windows (PowerShell)">
    ```powershell
    pg_dump -Fc -U postgres patchwork > patchwork-backup.dump
    # Restore:
    pg_restore -d patchwork --clean --if-exists -U postgres patchwork-backup.dump
    ```
    Copy the MinIO data directory (default `./.minio-data` or your configured MinIO path) while MinIO is stopped.
  </TabItem>
  <TabItem label="Linux (bash)">
    ```bash
    sudo -u postgres pg_dump -Fc patchwork > /var/backups/patchwork-$(date +%F).dump
    sudo rsync -a --delete /var/lib/minio/data/ /var/backups/minio-data/
    ```
  </TabItem>
</Tabs>

## Uninstalling

Run `npm run stop`, then run `node scripts/setup.mjs --action=reset` (or stop `patchwork.service` and `minio.service`, drop the `patchwork` database, and delete `.env` and the MinIO data directory).

## Expected Result

`node scripts/setup.mjs --check` reports a complete, healthy installation (including the embedded `documentation-dist/` bundle), `/api/health` returns `200 OK`, and `/documentation` serves the built-in documentation site on the same origin.

## Troubleshooting

- **Unconfirmed admin setup token detected**: Run `npm run setup` and select **Reset** to clear the partial install and issue a fresh token.
- **PostgreSQL auth failure**: Verify `DATABASE_URL` in `.env` matches your local `postgres` password.
